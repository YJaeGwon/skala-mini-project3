개선 1

RAG 매뉴얼 검색

27% → 100%정답 매뉴얼 선택률

장애 대응 매뉴얼(runbook)을 고르는 방법을 단어 찾기에서 의미 검색으로 바꿨습니다. 문제가 있는 시스템마다 맞는 매뉴얼을 따로 찾습니다.

Before

알림 문구에 "cpu", "memory" 같은 단어가 있는지 위에서부터 찾아 처음 걸린 매뉴얼 1개만 골랐습니다. 문제가 두 개면 하나를 놓치고, 목록에 없는 새 장애는 엉뚱한 "DB 다운" 매뉴얼을 가져왔습니다.

After

매뉴얼을 벡터 DB에 저장해 두고, 시스템마다 "상태 + 알림 + 에러 로그"로 뜻이 가장 가까운 매뉴얼을 찾습니다. 새 매뉴얼 파일을 넣기만 하면 코드를 고치지 않아도 검색됩니다.

코드: agent/rag/ · agent/nodes/runbook_agent.py — 키워드 규칙 6/8 → 의미 검색 8/8 (오프라인 실험)

개선 2

사실 검증

27% → 0%환각 비율

답변을 내보내기 전에 검사하는 기준을 "형식"에서 "내용이 사실인지"로 넓혔습니다.

Before

30자 이상이고 "1)"이 들어 있으면 합격이었습니다. 측정하지도 않은 시스템의 "CPU 53.5%" 같은 지어낸 숫자도 그대로 통과했습니다.

After

형식 검사는 유지하고, 답변 속 숫자가 실제 측정값·알림·로그·매뉴얼에 있는지, 조사하지 않은 시스템을 원인으로 단정하지 않았는지 코드로 대조합니다. 틀리면 이유를 주고 다시 쓰게 하고, 3번 실패하면 측정값만 옮긴 안전한 답변으로 바꿉니다.

Before · graph.py
ok = len(draft) >= 30 and "1)" in draft
if not ok and attempts >= 3:
    ok = True   # 3회째는 통과 처리
After · validators.py
failures = (check_format(draft)          # 형식
          + check_numbers(draft, collected) # 숫자 출처
          + check_systems(draft, targets))  # 조사한 시스템만
# 3회 실패 → fallback_report(collected)

코드: agent/validators.py · agent/nodes/validate.py — 화면에서는 진행 단계가 "검수 통과"(Before)에서 "사실 검증 통과"(After)로 바뀝니다.

Before · 실제 진행 단계

After · 실제 진행 단계

개선 6

LLM을 부르는 동안 서버 전체가 멈추던 방식을 비동기 호출로 바꾸고, 답변을 글자가 만들어지는 대로 화면에 보냅니다.

Before · openai_llm.py
resp = httpx.post(OPENAI_URL, ...)   # 동기 호출
# async 노드 안에서 이벤트 루프가 멈춤

응답 시간 단축은 Base에 있던 고정 지연(작업당 0.35초) 제거와 불필요한 조사 감소의 영향이 더 큽니다.

추가 1

위험 조치 승인 (HITL)

24% → 0%승인 없이 나간 위험 조치

재시작, 롤백, failover처럼 서비스를 멈출 수 있는 조치가 답변에 들어가면, 바로 보내지 않고 운영자 승인을 받습니다.

Before

위험 조치를 걸러내는 단계가 없어서 "즉시 재시작을 권장합니다"가 그대로 나갔습니다.

After

위험 조치를 "실행하라"는 문장을 찾으면(재시작 여부 "확인" 같은 점검 문장은 제외) interrupt()로 멈추고 승인 카드를 띄웁니다. 승인하면 그대로 보내고, 거절하면 위험 조치를 뺀 대안으로 다시 씁니다. 대기 상태는 SQLite에 저장돼 서버를 재시작해도 이어집니다.

코드: agent/nodes/risk_gate.py · server.py의 /approve · 위험 패턴 data/risk_policy.json
