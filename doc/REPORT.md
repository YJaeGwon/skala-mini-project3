## 4. 실험 설정
- **Before**: 원본 `all_total_vue_student` 코드를 바이트 단위로 그대로 복사하고(`eval/before_snapshot.py`가 동일성 검사), 데이터(monitoring.json, runbooks)만 After와 같게 맞췄다. 원본 폴더는 수정하지 않았다.
- **After**: `task1_improved`.
- **공통 조건**: `LLM_BACKEND=openai`, fast·quality 모두 gpt-4o-mini, 임베딩 text-embedding-3-small, 채점 gpt-4o.
- **데이터셋**: `eval/dataset.jsonl` 28건(dev 10 / test 18). Base 회귀 쿼리 10개를 포함하고, 복합 장애·신규 장애·증상만 말한 문의·대상 불명·후속 질문·긴 대화·위험 조치 문의를 넣었다.
- **채점**: 응답 이벤트에서 조사한 시스템과 runbook을 뽑아 코드로 채점하고, 진단 근거·환각·유용성은 gpt-4o가 채점했다.
- **수치 근거 판정**: MCP가 지표에 무작위 변동(jitter)을 더하므로 기준값 ± 변동 범위 또는 알림·로그·runbook에 있는 숫자면 근거 있는 수치로 봤다.
- **비용**: 가상 비용은 Base와 같은 방식(토큰 × 역할별 1k당 단가)으로 계산했다. 실제 OpenAI 사용료는 평가 전체를 합쳐 1달러 미만이다(추정).

## 7. 한계와 트레이드오프

| # | 한계 | 근거 | 완화 / 추가 개선 |
|---|---|---|---|
| L1 | **비용 증가** | 요청당 가상 비용 ×1.7 — 로그·다중 runbook으로 프롬프트가 길어지고, 요약 호출이 추가됨 | 로그 줄 수 제한(현재 5줄), 요약은 메시지 10개를 넘을 때만 |
| L2 | **평가 규모가 작음** | 합쳐서 38건이고 확인 질문 4건·긴 대화 2건뿐. 개발용 질문은 개선 기능을 알고 만들었고, 채점도 LLM | 질문 확대, 일부 사람 교차 채점, 실제 장애 티켓·운영 피드백으로 재평가 |
| L3 | **운영자 승인 부담** | 장애 답변의 35.7%가 승인 요청 | 위험 패턴을 시스템 중요도별로 차등, 승인 이력으로 자동 승인 규칙 학습 |
| L4 | **위험 조치 탐지가 패턴 기반** | 단어 목록과 제외 문맥에 의존. 영어·다른 표현은 놓칠 수 있음 | LLM 분류기를 보조로 쓰거나 runbook 단계별 위험 등급 메타데이터 |
| L5 | **RAG 운영 비용** | 검색마다 임베딩 API 호출(약 0.27초), runbook이 바뀌면 재인덱싱(해시로 자동) | 질의 임베딩 캐시 |
| L6 | **요약 메모리의 정보 손실 가능성** | 실제로 요약 덮어쓰기 버그가 있었음. 프롬프트로 막았지만 보장은 아님 | 중요 사실(이름·사번·시스템)은 구조화 필드로 따로 저장 |
| L7 | **지연 개선의 원인** | p50 −0.7초는 주로 Base의 고정 지연(0.35초 × 작업 수) 제거와 불필요한 조사 감소 덕분. 병렬 서브에이전트 자체의 속도 기여는 작음 | — |
| L8 | **수치 검증의 근사성** | 측정값 변동 범위로 판정. 단위(%·s·ms)만 검사 | 측정값을 응답 메타데이터로 노출해 정확 대조 |
| L9 | **ollama 경로 미검증** | bge-m3·qwen3 조합은 실행해 보지 않았고, 임계값도 미보정 | 로컬 모델로 같은 평가 실행 |
| L10 | **승인 대기 목록** | `/pending`은 메모리 기반(재시작 시 목록만 사라지고 승인은 가능) | checkpointer 조회로 대체 |
